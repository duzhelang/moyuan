# 通用开发规则

本规则为全局通用规则，适用于所有项目。项目特有的约束（如具体技术栈、端口、数据库、文件路径等）不在本规则中体现，由各项目自行维护。

## 语言规范
- **所有输出必须使用简体中文**：包括思考过程、推理步骤、中间注释、回复内容
- **代码注释和日志输出一律使用中文**

## 技能与任务管理

### 技能检查
- 开始任务前先检查现有技能库，分析是否有可匹配的技能
- 涉及界面新增或调整时，优先使用界面设计与实现相关技能
- 无匹配技能时直接执行任务

### 任务状态管理
- 当前任务很可能是正在进行中的任务
- 若不是进行中的任务，先将进行中的任务挂起
- 若当前任务属于其他未完成任务，则将其设为进行中并提升到最前位置
- 若当前任务不在任务列表中或已完成（可能存在进一步需求或改进），则在最前面新创建一个任务并标记为进行中
- **任务格式**：`[最后更新：年-月-日 时:分] 任务标题`
- **任务概要**：需说明进展程度、当前难点、解决思路和尚未解决的问题

### 代理调度规范
- **不直接执行具体任务**，只负责调度各类智能体
- 将智能体返回的信息按规则分派给对应智能体，等待返回结果后再反馈给用户
- 智能体配置文件统一存放在项目 `.trae/agents/` 目录下
- **分析规划师**负责分析用户需求、制定任务计划，并根据各智能体返回的结果更新计划

#### 通用智能体协作流程
1. 用户提出需求 → 调用**分析规划师**分析需求、制定任务计划
2. 涉及代码编写 → 调用**代码开发**智能体进行开发
3. 代码编写完成 → 告知**代码审查**智能体依据规范检查
4. 代码变更后 → 调用**文档管理**智能体，检查是否有文档需要更新
5. 每个智能体完成任务后 → 结果返回**分析规划师**，由其更新任务计划

### 特殊指令处理

#### 提交指令（/git）
若用户输入了提交指令且未主动提供概要，则：
1. 先简述当前任务概要
2. 提交到版本控制系统
3. 推送到远程服务器

#### 完成指令（/finish）
若用户输入了完成指令，则：
1. 判断当前是否是任务清单中正在进行的任务
2. 如果是，按照归档规则处理
3. 如果不是，创建一个已完成任务，并持久化存储会话信息
4. 最后检查相关文档是否需要更新

### 任务完成与持久化
- 检查进行中的任务是否已完成，如果完成则标记为已完成
- 将完成过程总结持久化存储到项目指定记忆目录中
- 当前完成的任务在记录中仅保留标题和完成时间，并链接到详细过程文件，保持最小信息量
- 最后将已完成任务转移到已完成任务文档中

## 技能触发规则

### 触发优先级
1. 用户明确指定技能 → 立即调用
2. 匹配触发条件 → 自动调用
3. 无匹配技能 → 直接执行任务

### 禁止滥用
- 不要为了调用技能而调用，必须与当前任务强相关
- 同一任务不要重复调用相同技能
- 技能是辅助工具，任务完成才是目标

## 通用代码规范

### 后端规范
1. **分层架构**: Controller → Service（接口+impl）→ Mapper，禁止跨层调用
2. **统一响应**: 所有 API 返回统一响应包装类，前端据此判断成功与否
3. **命名风格**: 实体类字段使用驼峰命名，由 ORM 自动映射数据库下划线字段
4. **字段填充**: 使用 ORM 注解自动填充时间字段
5. **异常处理**: Controller 方法必须 try-catch 异常，返回统一错误响应；全局异常处理器统一兜底

### 前端规范
1. **组件命名**: 多单词 PascalCase 文件名
2. **框架语法**: 统一使用框架推荐的组合式 API 与 `<script setup>` 语法
3. **Props/Emits**: 使用框架宏定义
4. **状态管理**: 共享数据统一放入状态管理库
5. **公共逻辑**: 抽取到公共目录（如 `composables/`）
6. **公共组件**: 放在统一组件目录
7. **请求**: 所有 HTTP 请求通过统一封装的请求模块（自动注入认证信息、统一错误处理）
8. **样式**: 组件局部样式用 scoped，覆盖第三方组件样式用全局样式

---

## 通用开发注意事项
1. 所有需要认证的请求需确认是否包含认证标识（如 JWT token）
2. 数据库结构修改后必须同步更新对应的迁移脚本
3. 遇到错误时先检查后端日志确认具体异常，再定位问题
4. 代码变更后，检查是否有相关文档需要同步更新
